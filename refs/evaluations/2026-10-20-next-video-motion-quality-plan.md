# Next Video Motion Quality Plan

## Accepted checkpoint

The current production checkpoint is
`video_raise_the_neon_black_full_visualizer_v2.json`, generated by
`scripts/build_infra_choir_raise_neon_black_full_video.py`. It uses the reviewed
cached motion clip at full strength and composites localized lighting, title,
wordmark, and the 2048-band EQ over the moving frames. The delivered v2 file is
208.25 seconds of 1920x1080 H.264 at 16 fps with stereo 48 kHz AAC. Motion was
measured at five points from 8 through 200 seconds. The user accepted this as
an improvement but identified a visible screen jump and residual fuzzing.

This checkpoint is song-specific evidence, not a template for future source
art, audio, prompts, or target masks. Rebind every new run to the user-selected
production inputs.

## Findings

### Screen jump

The current motion asset contains 158 prepared frames and is repeated across
the song. Measurement of the delivered v2 file confirmed the report: median
adjacent-frame change at each 158-frame boundary is 9.44 luma levels versus
1.49 for ordinary frames. The old overlap implementation blended the tail
toward head frames 0 through 12 and then reset to head frame 0, producing a
large backward step at every wrap.

The renderer now uses a true `N-overlap` period. It starts after the consumed
head segment, plays the middle, blends the tail into head frames 0 through
`overlap-1`, and continues at head frame `overlap`. A regression test rejects
the former end-of-crossfade reset. A 12-second real production-path probe
rendered 192 frames with the same cached motion, lighting, title, wordmark, and
2048-band EQ. Its corrected boundary measured 1.55 luma levels versus a 1.29
ordinary-frame median and 1.92 ordinary 95th percentile; the complete overlap
window peaked at 2.54 instead of the old 9.59 boundary maximum. This repairs the
deterministic indexing defect, but the next candidate must still pass visual and measured seam gates;
a cross-dissolve cannot correct incompatible camera position, large subject
displacement, or motion phase and can still create doubled/soft frames.

Before the next full-song render, measure the candidate clip itself and the
assembled probe at every cycle boundary. Report ordinary adjacent-frame change,
boundary change, phase-correlation shift, and protected-subject change. Reject
the candidate if a boundary is a visible outlier even when its aggregate median
passes.

Preferred repair order:

1. Select a naturally compatible sub-range whose end pose and motion phase
   match its beginning.
2. Build a motion-compensated seam or generate an explicitly cyclic candidate.
3. Compare a short ping-pong loop only as a diagnostic; reject it when waves,
   smoke, flags, or hair visibly reverse.
4. Do not use a longer dissolve merely to conceal a bad seam because it can
   increase ghosting and fuzz.

### Fuzzing

The current path performs generated-video encoding, temporal atmosphere
amplification and another encode, cached-video decode/stabilization, 1080p
scaling, overlay compositing, and final H.264 encoding. The fuzz can therefore
come from model texture instability, stabilization/resampling, the temporal
amplification pass, loop cross-dissolve ghosting, or repeated lossy encoding.

The next probe must retain lossless or near-lossless intermediates through the
comparison and encode only the review deliverable. Run A/B crops for the lead
face/hair, clouds/fog, flags, water, tentacles, and high-detail static structures.
Measure temporal variance in protected static areas separately from intended
motion. Compare the raw generated frames, the looped intermediate, the
stabilized/scaled intermediate, and the final encode so the responsible stage
is identified before tuning.

## Wan 2.1 VACE 1.3B exploration

No VACE or 1.3B checkpoint is installed in the current Comfy model tree. Do not
silently substitute another Wan model and do not download weights during normal
validation.

The official VACE project supports reference-to-video, video-to-video, and
masked video-to-video workflows. Its Wan 2.1 VACE 1.3B release targets roughly
81 frames at 480p/832x480; the Wan documentation warns that 720p is less stable
for the 1.3B model because it received limited training at that resolution.
This makes 832x480 the first fair quality/runtime gate on the 12 GB RTX 4070,
followed by deterministic upscaling only if the source-resolution result passes.

The first benchmark should be a separate workflow and output prefix, with one
fixed seed and no full-song assembly. Use the next user-selected artwork, not
the Raise the Neon Black image by assumption. Test a reference/masked animation
configuration that protects the lead face, body, architecture, and other static
geometry while allowing independently specified motion for atmosphere, hair,
waves, flags, and tentacles when those elements exist in the selected artwork.

Record wall time, peak VRAM, CPU offload, source similarity, static-region
temporal variance, target-region optical flow, seam measurements, and a visual
artifact review. VACE advances only if it:

- produces useful target motion without whole-frame drift or invented content;
- improves temporal cleanliness over the accepted Wan candidate;
- can form a non-jumping loop without a visibly fuzzy dissolve;
- fits the current hardware without an impractical runtime; and
- survives deterministic lighting/title/EQ compositing in an 8-second probe.

If it fails, retain the current short-generation plus deterministic compositor
architecture and focus on better cyclic source generation, lossless
intermediates, and motion-compensated seam construction.
